# Takimoto Presentation Generator

瀧本ゼミの株式投資推奨発表資料を生成するスキル。markdownで書かれたストーリーと決算短信PDFから、Google Sheets/Slidesにインポート可能なスプレッドシート(.xlsx)とスライド(.pptx)を出力する。

## 起動条件

ユーザーが以下のような依頼をしたとき:
- 「瀧本ゼミ形式で資料作って」「瀧本ゼミの発表資料生成」
- 「投資推奨のスライド・スプシ作って」
- 入力markdown(`samples/*.md`形式)を渡してきて発表資料化を依頼

## 必要な入力

| 入力 | 必須? | 形式 | 用途 |
| :---- | :---- | :---- | :---- |
| ストーリーmarkdown | **必須** | `samples/*.md`の構造に従う | スライド+スプシの骨組み・物語・仮定 |
| 決算短信PDF (有報・半期報) | スプシ生成に必須 | TDnet/EDINET配布のPDF | 過去実績の数値、セグメント情報、KPI |
| ユーザーが直接指定する数値 | 任意 | 質問で取得 | PER感応度、ピア企業の選定 |

`samples/4112-hodogaya.md` を入力markdownの参照モデルとせよ。発表者・推奨・投資期間・章立て・因数分解表・ミスプライシング表・章別本文・Appendixが揃った構造。

## 設計原則

**Python(決定的) と Opus(柔軟) で役割を分ける**:

| 担当 | やること |
| :---- | :---- |
| **Python** | スタイル強制(色/カンマ/インデント/グラフ)、PDF抽出、ファイル書出し、検証(青セル備考チェック等) |
| **Opus(あなた)** | 因数分解の式評価、FY26+のプロジェクション計算、ナラティブ生成、ピア企業選定、用語解説の文言、ストーリー整合性 |

つまり**算術や仮定の計算は自分で実行する**。Python側に計算ロジックを足そうとせず、結果値を構造体に詰めて渡せ。

## ワークフロー

### Step 1: 入力を理解する

1. ユーザー提供の markdown を読む。次の要素を抽出する:
   - 銘柄コード・社名
   - 推奨(BUY/SELL)
   - 目標株価・投資期間・発表者
   - **因数分解の式**(0️⃣セクションの ```...``` ブロック)
   - **因数の年度別予想値**(因数表の方向矢印・%等)
   - シナリオ(Bear/Base/Bull)
   - Appendix項目(ダウンサイド・前回QA・現地調査など)
   - **文体・熱量**(「BUY!!!」型 / 分析型 / 物語型 / 体感報告型)

2. 決算短信PDFが渡されている場合、`scripts/extract_yuho.py` を使って:
   - 連結P&L (売上・粗利・販管費・営利・経常・純利益)
   - 販管費内訳
   - セグメント別売上(地域別/事業別)
   - 主要経営指標等(5年推移)
   - 発行済株式数・EPS
   - 製品別売上(yuho本文 「売上高の内訳」検索)

   結果は `dict` 形式でメモリ保持。

### Step 2: スプレッドシート(.xlsx)生成

1. `reference/sheet_structure.md` を読んでスプシの行構造規約を確認する
2. 因数分解を読み、各因数の年度別値(FY26/FY27)を**自分で計算**する。例:

   ```
   markdown: 「GPU向け基板 25/26/27年で +30/20/10%」
   → FY24=1.0, FY25=1.30, FY26=1.56, FY27=1.72
   
   markdown: 「層数 Hopper12/Blackwell14/Rubin18」+ 世代比率表
   → 加重平均で各年度の値を算出
   ```

3. P&L構造を組み立てる。実績(yuho)+予想(自分で計算)を年度カラムに並べる
4. `scripts/sheet_renderer.py` の `Row` `SheetConfig` `ChartSpec` データクラスにすべて詰める
5. `render(config, output_path)` 呼び出し
6. TODOが残った場合は `reference/asking_user.md` に従ってAskUserQuestionで取得

#### スプシ必須要素

- 因数分解の上位行(売上トップ→セグメント→製品)
- P&L (売上→原価→粗利→販管費の内訳→営業利益→経常→純利益)
- 営業利益率(%)・粗利率(%)等の比率行
- 重要度★/★★/★★★ (markdown の「最重要」「核心」等から判定)
- 備考(全独立変数=青セル に必須)
- 「織り込み済み?」反論ブロック(時価総額据置で純利益増→PER低下)
- ピア比較ブロック(同業3社程度。純粋同業がなければ業態/モデル/価格戦略/地域で多軸選定)
- グラフ3つ程度: 売上+利益(棒)+利益率(線・第二軸)/ ドライバー因数の推移 / 工場稼働率 等

### Step 3: スライド(.pptx)生成

1. `reference/slide_structure.md` を読んでスライド章立て規約を確認
2. markdownの`##`/`###`を1〜3枚のスライドに展開する判断:
   - `### **○○とは**` ブロック → 用語解説スライド1枚
   - markdown表 → そのまま表スライド1枚
   - ASCIIブロック図 → 構造図テキストスライド1枚
   - 箇条書きの長い段落 → 詰め込みすぎないよう必要なら分割
3. 章の境目で目次再掲スライドを挿入(4本のサンプル参考)
4. 表紙・ストーリー要旨・因数分解・ミスプライシング・各章本文・Appendix を Slide オブジェクトのリストとして組み立て
5. 画像が必要な箇所は `[画像: 説明文]` プレースホルダのテキストブロックを置く(画像生成しない)
6. `scripts/pptx_renderer.py` の `Slide` `SlideDeckConfig` データクラスに詰めて `render(config, output_path)` 呼び出し

#### スライド必須要素

- 表紙 (銘柄コード+社名+推奨+目標株価+投資期間+発表者)
- 📍 発表を理解するための地図
- 0️⃣ ストーリー要旨 + 因数分解 + ミスプライシング
- 目次
- 1️⃣ 基本情報 / 2️⃣ マクロ / 3️⃣ ミクロ / 4️⃣ バリュエーション / 5️⃣ Appendix
- 章の境目で目次再掲

### Step 4: 検証

- Python側の `render` 関数が以下を自動チェック:
  - 青セルに備考がない(警告)
  - TODO残値(警告)
- 出力後、自分でリストアップ:
  - 因数分解の式と数値の整合性 (例: 「GPU生産+30% × 層数+8%」と表中の値の積が一致するか)
  - スライドと.xlsxのストーリー整合性 (スライドが言う数字とスプシの数値が一致するか)
  - 1スライドに情報詰めすぎていないか

## トーン合わせ

入力 markdown の文体を読み取って出力に反映せよ:

| 文体タイプ | 例 | 出力での反映 |
| :---- | :---- | :---- |
| 熱量型 | メック「よってBUY!!!」、かわでん「STRONG BUY!!」 | 「!」を要所で使う、強気な動詞(爆発・跳ね上がる) |
| 分析型 | 保土谷「アナリスト0社、構造的転換点」 | 数値と論理中心、感情語は控えめ |
| 物語型 | ムービン「25年保守経営からの覚醒」 | 時系列の語り、変曲点の強調 |
| 体感報告型 | AlbaLink「現地で査定申し込んでみた」 | 体験談・一人称、具体的なフレーズ引用 |

## やっちゃダメなこと

- **画像生成しない** — `[画像: 説明]` プレースホルダで止める
- **markdownにない数値を捏造しない** — 不明なら TODO のまま残し、AskUserQuestion で確認
- **スタイルルールを破らない** — 黒/青、カンマ、インデント、グリッド線オフ、固定枠は機械的に守る
- **1スライドに情報詰めない** — 情報量多いなら分割するか捨象する
- **業績タイプを保土谷型(持分法)に決めつけない** — markdownの因数分解を素直に読む
- **PER議論を比較なしで終わらせない** — ピア(多軸選定)+「織り込み済み反論」両方入れる

## ファイル構造

```
.claude/skills/takimoto-presentation/
├── SKILL.md                    ← 本ファイル
├── reference/
│   ├── slide_structure.md      ← スライド章立て規約 (詳細)
│   ├── sheet_structure.md      ← スプシ行構造規約 (詳細)
│   ├── factor_decomp_patterns.md ← 業績タイプ別の因数分解パターン例
│   └── asking_user.md          ← 質問の出し方(PER, ピア企業 等)
└── scripts/
    ├── sheet_renderer.py       ← スプシレンダラー(スタイル強制)
    ├── pptx_renderer.py        ← スライドレンダラー
    └── extract_yuho.py         ← yuho PDF抽出ユーティリティ
```
