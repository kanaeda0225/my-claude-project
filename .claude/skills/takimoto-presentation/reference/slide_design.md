# スライド設計原則 (Visual Design Checklist)

「機械的に動く」と「人間に見せられるクオリティ」のギャップを埋めるための原則。`pptx_renderer.py` がデフォルトで強制するルール+Opus(あなた)がスライド config を組むときに守るべきガイドライン。

## フォントサイズ最小値 (絶対遵守)

| 要素 | 最小サイズ | 推奨 |
| :---- | :---- | :---- |
| タイトル | **28pt** | 28-32pt |
| サブタイトル / 一言メッセージ | **20pt** | 20-22pt (ボールド + アクセント色) |
| 本文(箇条書き) | **18pt** | 18-20pt |
| 表のヘッダー | **14pt** | 14-16pt (ボールド) |
| 表のセル | **13pt** | 13-15pt |
| 出典フッター | **10pt** | 10-12pt (グレー) |
| 画像プレースホルダ内のテキスト | **18pt** | 18-22pt |

→ **これより小さいフォントは絶対に使わない**。情報が入りきらないならスライドを分割するか捨象する。

## 1スライド1メッセージの定義

「1メッセージ」=スライド見出しの下にある「一言で言いたいこと」が1つだけ。

例:
```
タイトル: 銅箔面積: GPU向けは大判化で爆発
サブタイトル(=メッセージ): HopperからRubinまでで面積3倍
本文: 世代別面積表 + 引用
```

→ 表やリストの背景にある「読み手に持ち帰ってほしい1行」を **サブタイトルとして必ず明示**する。

### 本文の量制限

- 箇条書きの場合: **最大5項目** (それ以上は分割)
- 1項目の文字数: **30字以内** (それ以上はサブ箇条書きに分解 or 短く)
- スライド全体の本文文字数: **目安180字以内**
- 表の行数: **最大7行**
- 表の列数: **最大4列**

## 視覚階層(タイトル → メッセージ → 根拠)

各スライドは3層構造で組む:

```
┌────────────────────────────────────────┐
│  [Layer 1] タイトル                    │ ← 何の話か(28pt)
│                                        │
│  [Layer 2] サブタイトル/一言メッセージ │ ← 結論(20pt ボールド色付き)
│                                        │
│  [Layer 3] 本文(箇条書き or 表 or 図)  │ ← 根拠(18pt)
│                                        │
│  出典: ○○○○○                          │ ← 出典(10pt グレー)
└────────────────────────────────────────┘
```

## 色パレット

| 用途 | 色 | RGB |
| :---- | :---- | :---- |
| タイトル / メインアクセント | ディープブルー | `1F4E78` |
| 強調(増減・重要数値) | アクセントレッド | `C0392B` |
| ポジティブ強調(良い動き) | アクセントグリーン | `2E7D32` |
| 本文 | ニアブラック | `202020` |
| 補助テキスト | グレー | `666666` |
| 出典フッター | ライトグレー | `808080` |
| テーブルヘッダー背景 | ディープブルー | `1F4E78` (白文字) |
| テーブル奇数行背景 | 極薄グレー | `F5F5F5` |
| 章ディバイダー背景 | ディープブルー | `1F4E78` (白文字大見出し) |

## 余白

- スライド端からテキストまで: 最低 **0.5 inch**
- タイトル下から本文まで: 最低 **0.2 inch**
- 表とフッターの間: 最低 **0.3 inch**
- 箇条書きの行間: **1.3倍** (詰まりすぎないよう)

## テーブルの見栄え

機能要件:
- ヘッダー行は **濃色背景 + 白文字 + ボールド**
- 奇数データ行は **極薄グレー背景** (ストライプ)
- 列幅は内容に応じて配分(数値列は狭く、説明列は広く)
- 数値列は **右揃え**
- ラベル列は **左揃え**

## 画像プレースホルダの正しい書き方

❌ 悪い例:
```
[画像: A6ライン]
```

✅ 良い例:
```
[画像]
Samsung Display A6ライン (天安工場) の航空写真
出典候補: Samsung Display IR / The Elec の報道写真
サイズ目安: スライド中央に 横6inch × 縦4inch 程度
```

→ 画像プレースホルダには **(a)何の画像か (b)どこから入手するか (c)サイズ感** の3点を必ず書く。

### よく使う画像プレースホルダパターン

- グラフ系: 「ここに ○○の YoY推移(縦軸: ○○、横軸: 年度、棒グラフ)。出典 ○○」
- 構造図: 「ここに ○○のサプライチェーン図」 → 可能なら ASCII図に置換した方がよい
- 製品写真: 「ここに 製品○○の写真。出典 公式IR画像」
- 統計グラフ: 「ここに 業界規模推移グラフ。出典 ○○調査」

## スライドキンドの使い分け

| kind | 使う場面 |
| :---- | :---- |
| `cover` | 表紙のみ(自動生成) |
| `chapter` | 1️⃣ 基本情報 / 2️⃣ マクロ など章のディバイダー |
| `toc` | 目次 + 章の境目での目次再掲 |
| `content` | 標準的な箇条書きスライド |
| `table` | 表が主役のスライド |
| `ascii` | 構造図・式・フロー図 (等幅フォント) |
| `image_placeholder` | 写真・グラフが入る箇所 |

## やってはいけないこと(再掲)

- フォントサイズを最小値より小さくしない
- 1スライドに6箇条以上の箇条書きを置かない
- 「サブタイトル(一言メッセージ)」を省略しない
- 出典が markdown にあるのに スライドフッターに書かない
- 画像プレースホルダを `[画像: ○○]` 1行で終わらせない (具体的な指示を)
- ASCII図で表現できる構造図を `image_placeholder` にしない
- markdownにない数値を書かない

## スライド枚数のレンジ

業界・企業の複雑さで増減するが、目安:

- シンプルな銘柄: 25-30 枚
- 標準的な銘柄: 30-40 枚
- 詳細な銘柄(現地調査・前回QA含む): 50-70 枚

サンプル参考: メック27p / ムービン25p / かわでん39p / AlbaLink72p / 保土谷(理論)40p

## 自己レビューの観点

スライド config を組み終えたら、以下を自分で確認:

1. **タイトルだけ並べて読んで、ストーリーが追えるか?**
2. **各スライドに「一言メッセージ(サブタイトル)」が入っているか?**
3. **表がある場合、ヘッダーは適切か?数値の桁数は揃っているか?**
4. **画像プレースホルダがあれば、内容が具体的か?**
5. **章の境目で目次再掲が入っているか?**
6. **出典フッターが必要な箇所に入っているか?**
